# Грамматика и семантика языка Magnum

Исходник грамматики для lark — [`magnum/grammar.lark`](magnum/grammar.lark) (LALR(1), контекстный лексер).
Ниже — та же грамматика в EBNF и правила, по которым движок исполняет модель.

## Лексика

| Терминал | Вид | Пример |
|---|---|---|
| `NAME` | буква/`_`, далее буквы, цифры, `_` (кириллица допустима) | `count_client`, `выручка` |
| `NUMBER` | `123`, `1.5`, `.5`, `1e-3` | |
| `DURATION` | число + единица `w`/`d`/`h`/`m`/`s` | `1d`, `30m`, `1.5h` |
| `STRING` | в двойных кавычках, `\"` — экранирование | `"Сумматор"` |
| комментарий | `#` до конца строки | `# коммент` |

Пробелы и переводы строк незначимы: операторы разделяются просто пробелом или новой строкой.
Длительность всегда переводится в **дни**: `1w = 7`, `1d = 1`, `1h = 1/24`, `1m = 1/1440` (**минута**), `1s = 1/86400`.

Ключевые слова: `model controls default limits in function return event do trigger every arrival on start when choose emit after call instant and or not push pop remove clear seize release`. Имена `queue` и `resource` — конструкторы, а не ключевые слова. Имя `if` зарезервировано за условным выражением.
Не используйте их как имена переменных. Имена встроенных функций (`sum`, `max`, …) как переменные использовать можно — `sum = sum + 1` работает, у функций и переменных разные пространства имён.

## Синтаксис (EBNF)

```ebnf
model         = "model" STRING "{" { controls | function | event } "}" ;

(* ---------- controls ---------- *)
controls      = "controls" "{" { defaults | limits } "}" ;
defaults      = "default" "{" { NAME "=" expr } "}" ;
limits        = "limits" "{" { NAME "in" lower "," upper } "}" ;
lower         = ( "[" | "(" ) expr ;            (* [ — включая, ( — не включая *)
upper         = expr ( "]" | ")" ) ;

(* ---------- функции ---------- *)
function      = "function" NAME "(" [ params ] ")" "{" { assignment | print | "return" expr } "}" ;
params        = NAME { "," NAME } ;

(* ---------- события ---------- *)
event         = "event" NAME [ "(" [ params ] ")" ] "{" { section } "}" ;
section       = do | trigger | choose | emit ;
do            = "do" "{" { assignment | print | queue_stmt } "}" ;
queue_stmt    = "push" NAME "(" expr ")" | "remove" NAME "(" expr ")" | "clear" NAME
              | target "=" "pop" NAME | "seize" NAME | "release" NAME ;
print         = "print" "(" [ ( expr | STRING ) { "," ( expr | STRING ) } ] ")" ;   (* отладочный вывод *)
trigger       = "trigger" "{" { "every" expr
                              | "arrival" NAME "(" [ arguments ] ")"
                              | "on" "start"
                              | "when" expr } "}" ;
choose        = "choose" "{" { expr ":" emit } "}" ;
emit          = "emit" NAME [ "(" [ arguments ] ")" ] [ "after" expr ] ;

(* ---------- присваивание ---------- *)
assignment    = target "=" expr ;
target        = ( NAME | instant ) { "[" expr "]" } ;
instant       = "instant" "[" NAME "]" ;

(* ---------- выражения (по возрастанию приоритета) ---------- *)
expr          = or_expr ;
or_expr       = and_expr { "or" and_expr } ;
and_expr      = not_expr { "and" not_expr } ;
not_expr      = "not" not_expr | comparison ;
comparison    = sum [ ( "<" | "<=" | ">" | ">=" | "==" | "!=" ) sum ] ;   (* без цепочек a < b < c *)
sum           = product { ( "+" | "-" ) product } ;            (* левоассоциативно *)
product       = unary { ( "*" | "/" ) unary } ;
unary         = ( "-" | "+" ) unary | power ;
power         = postfix [ "^" unary ] ;                         (* правоассоциативно *)
postfix       = atom { "[" expr "]" } ;
atom          = NUMBER | DURATION | NAME | instant
              | "call" NAME "(" [ arguments ] ")"               (* функция модели *)
              | NAME "(" [ arguments ] ")"                      (* встроенная функция *)
              | "[" [ expr { "," expr } ] "]"                   (* массив *)
              | "(" expr ")" ;
arguments     = argument { "," argument } ;                     (* позиционные, затем именованные *)
argument      = expr | NAME "=" expr ;
```

Следствия приоритетов: `-2^2 = -4`, `2^3^2 = 512`, `2^-1 = 0.5`, `10-3-2 = 5`, `a + 1 == b` — это `(a + 1) == b`, `x or y and z` — это `x or (y and z)`.

## Очереди и ресурсы

Очередь и ресурс создаются присваиванием — **только в `controls` или в `do` события**:

```
controls {
    default {
        count_masters = 3
        masters = resource(capacity = count_masters)   # ресурс как параметр модели
    }
}

event _init {
    do { clients = queue() }                           # FIFO-очередь чисел (например, номеров клиентов)
    trigger { on start }
}

event StartOrder {
    trigger { when free(masters) > 0 and size(clients) > 0 }
    do {
        instant[id] = pop clients
        seize masters
    }
    emit OrderDone after exponential(7m)
}
event OrderDone { do { release masters } }
```

| Создание | |
|---|---|
| `q = queue()` | пустая очередь |
| `r = resource(capacity = n)` или `r = resource(n)` | ресурс из `n` единиц, все свободны |

| Операция (в `do` события) | |
|---|---|
| `push q(x)` | добавить число `x` в хвост |
| `x = pop q` | взять из головы (цель — переменная, `instant[...]` или элемент массива); пустая очередь — ошибка |
| `remove q(x)` | убрать `x` из очереди, если он там есть (самое раннее вхождение); иначе ничего |
| `clear q` | очистить |
| `seize r` / `release r` | занять / освободить единицу ресурса; занять сверх `capacity` или освободить незанятое — ошибка |

| Функция (в любом выражении) | |
|---|---|
| `size(q)`, `first(q)`, `contains(q, x)` | длина, голова (без извлечения), есть ли `x` (1/0) |
| `free(r)`, `busy(r)`, `capacity(r)` | свободно / занято / всего единиц |

**В `controls`** очередь и ресурс создаются заново в начале каждого запуска и становятся параметрами модели:
* `capacity` ресурса вычисляется при запуске из остальных контролов (`resource(capacity = count_masters)` следует
  за переданным `count_masters`); можно задать и напрямую: `run(controls={"masters": 5})`. `limits` для ресурса
  ограничивают `capacity`;
* очереди можно передать начальное содержимое: `run(controls={"clients": [1, 2, 3]})`;
* в `result["controls"]` ресурс — его `capacity`, очередь — начальное содержимое.

**В `do`** присваивание создаёт новый объект при каждом выполнении: `clients = queue()` в ежедневном событии
начинает очередь заново. Пересоздание ресурса сбрасывает занятые единицы — `release` после этого даст ошибку.

Ограничения:
* Нигде больше `queue()` и `resource(...)` не пишутся: не в выражениях, не в функциях, не в `instant[...]`
  и не в элементах массивов — это ошибка при загрузке.
* Имя очереди всегда очередь: присвоить ему число нельзя, использовать в арифметике или передавать в функции модели —
  тоже, только через операции и функции выше. `print(q, r)` печатает их состояние.
* Обращение к очереди до её создания — ошибка выполнения с подсказкой.
* Все операции очереди — за O(1), независимо от длины.
* Изменения очереди и ресурса видны триггеру `when` (условие `size(q) > 0` проверяется после `push`/`pop`/`remove`).
* В результате (`variables`, `final`) очередь — список элементов от головы к хвосту, ресурс — число занятых единиц.

## Отладка: print

В `do` и в теле функции можно писать `print(...)` — выводит аргументы через пробел, как `print` в Python.
Аргументы — выражения и строки в двойных кавычках. Числа с целым значением печатаются без `.0`.

```
do {
    n = n + 1
    print("день", TIME, "n =", n, instant[t])    # -> день 3 n = 3 0.25
}
```

`print` выполняется в порядке записи вместе с присваиваниями. Для массовых прогонов вывод отключается:
`model.run(..., debug=False)` — на результат это не влияет.

## Условия

Отдельного логического типа нет: **истина — любое ненулевое число**, результат сравнения и логической операции — `1` или `0`.

* сравнения `< <= > >= == !=` (`==` и `!=` работают и для массивов);
* логика `and`, `or`, `not` — ленивая: `a > 0 and b / a > 1` не делит на ноль;
* условное выражение `if(условие, если_истина, если_ложь)` — вычисляется только выбранная ветка, можно вкладывать.

```
do {
    stock = if(stock > 0, stock - 1, stock)              # условное обновление
    price = if(day < 7, 100, if(day < 30, 90, 80))       # вложенный if
}
choose {
    if(stock < 3, 1, 0): emit Restock                    # условный emit
}
```

## Значения и переменные

* Значение — число (float) или массив (вложенный список чисел). Арифметика над массивами целиком не поддерживается, только через индексацию; индексы с нуля.
* **Глобальные переменные** — контролы и всё, чему присваивается значение в `do`. Создаются при первом присваивании; чтение до присваивания — ошибка выполнения.
  Именно они попадают в результат.
* **Параметры события** — только для чтения внутри этого события.
* **`instant[имя]`** — мгновенные переменные: живут одно срабатывание события, видны в `do`, `choose`, `emit`. В результат не попадают.
* **Внутри функции** любое присваивание создаёт локальную переменную; глобальные можно читать, но не менять. Функция обязана содержать `return`; рекурсия разрешена.
* Присваивание массива копирует его (`b = a; b[0] = 1` не меняет `a`).
* Зарезервированные имена: `TIME` — текущее моделируемое время в днях (только чтение; нельзя присваивать и использовать как параметр), `inf` — бесконечность (для `limits`). `time` в нижнем регистре — обычное имя.

## controls

* `default` вычисляется при загрузке, сверху вниз; значение может ссылаться на ранее объявленные контролы. Случайные функции запрещены.
* `limits`: `[a, b]`, `(a, b]`, `[a, inf)`, `(-inf, b)`… Неуказанный в `limits` контрол не ограничен. Для массива граница проверяется для каждого элемента.
* Проверяется и значение по умолчанию (при загрузке), и значения, переданные в запуск. Переданный массив должен иметь ту же форму, что и значение по умолчанию.
* `do` может менять значение контрола во время моделирования — `limits` при этом не проверяются (они ограничивают входные параметры модели, а не её состояние).

## Триггеры

| Триггер | Срабатывания |
|---|---|
| `on start` | один раз в момент `t = 0` (до любых периодических событий) |
| `every P` | `t = P, 2P, 3P, …` (первое — через период после старта). `P` вычисляется заново при каждом срабатывании, поэтому может зависеть от контролов и состояния |
| `arrival poisson(lambda=λ, per=T)` | пуассоновский поток, в среднем `λ` событий за время `T` (по умолчанию `per = 1d`). Интервалы ~ Exp(λ/T); λ пересчитывается после каждого прихода. `λ = 0` — событие не происходит |

| `when условие` | срабатывает в текущий момент, когда условие истинно (см. ниже) |

### `when` — ожидание условия

```
event StartOrder {
    trigger { when idle_masters > 0 and ptr < queue_size }
    do { ... }
}
```

* При загрузке движок определяет, от каких глобальных переменных зависит условие (включая переменные,
  которые читают вызываемые функции модели). Условие проверяется **только после событий, изменивших эти переменные**
  (присваивание, в том числе элементу массива), и один раз — после `on start`. Опроса по времени нет.
* Если условие истинно, событие ставится в очередь на текущий момент — после уже запланированных на этот момент событий.
  Пока оно ждёт выполнения, повторно не ставится.
* После выполнения события условие проверяется снова, если событие изменило его переменные: так `when` срабатывает
  столько раз подряд, сколько условие остаётся истинным (например, раздать всех ожидающих клиентов свободным мастерам).
  Если событие переменные условия не меняет — второго срабатывания не будет, пока их не изменит что-то другое.
* Событие обязано делать условие ложным (или менять его переменные так, чтобы оно стало ложным), иначе — бесконечная
  цепочка в один момент времени, её остановит `max_events`.
* В условии нельзя использовать `TIME` (для времени есть `every` и `after`), случайные функции и `instant[...]`.
  Условие должно зависеть хотя бы от одной переменной.

В одном `trigger` может быть несколько правил. Событие с параметрами не может иметь `trigger` — его можно только `emit`-ить.

## Порядок выполнения события

1. **trigger** — планируется следующее срабатывание (если событие запущено триггером);
2. **do** — присваивания в порядке записи;
3. **choose** — разыгрывается `u ~ U[0, 1)`, выбирается первая ветка, где `u < p₁ + … + pₖ`. Если `u ≥ Σp` — ничего не происходит. Каждая вероятность обязана быть в `[0, 1]`, сумма ≤ 1. Несколько блоков `choose` разыгрываются независимо;
4. **emit** — в порядке записи. Аргументы и задержка вычисляются в момент `emit`.

`emit X` без `after` выполняет `X` в тот же момент времени, но **после** текущего события и всех событий, уже запланированных на этот момент (очередь FIFO по моменту времени).

## Запуск и результат

```python
from magnum import load_model, load_model_file, run_model

model = load_model(text)              # или load_model_file("model.mgn")
result = model.run(
    controls={"value": 2},            # перекрывают default, проверяются по limits
    seed=42,                          # сид генератора
    horizon=365,                      # горизонт в днях
    sampling="1d",                    # политика снятия состояния (см. ниже)
)
```

### Политика `sampling`

| Значение | Что сохраняется |
|---|---|
| длительность: `"1d"`, `"6h"`, `"30m"`, `"1w"`, `"0.5d"` (или число дней) | снимок **всех** переменных в моменты `0, P, 2P, … ≤ horizon`. Снимок в момент `t` — состояние после всех событий с временем `≤ t`. По умолчанию `"1d"` |
| `"on_change"` | значение переменной в момент её изменения (точное время события). Начальные значения контролов — в момент 0. Несколько изменений в один момент схлопываются в итоговое; если значение в этот момент вернулось к прежнему — запись не создаётся |

Параметр `record=["a", "b"]` записывает в `variables` только перечисленные переменные (`final` по-прежнему содержит все).
Это заметно ускоряет расчёт и экономит память, особенно с `on_change` и большими массивами.

Изменением считается присваивание в `do` (в том числе элементу массива), после которого значение отличается от последнего сохранённого.

### Результат

```python
{
    "model": "Простой пример сумматора",
    "seed": 42,
    "horizon": 365.0,
    "sampling": "1d",
    "controls": {"value": 2.0},                    # фактически использованные контролы
    "variables": {                                 # для каждой переменной — моменты снимков и значения
        "value": {"time": [0.0, 1.0, ...], "value": [2.0, 2.0, ...]},
        "summa": {"time": [0.0, 1.0, ...], "value": [0.0, 2.0, ...]},
    },
    "final": {"value": 2.0, "summa": 730.0},       # состояние на горизонте
    "event_counts": {"_init": 1, "_set_value": 0, "_accumulator": 365},
}
```

Переменная появляется в `variables` с момента первого присваивания (раньше её снимков нет). События позже горизонта не выполняются.
Модель загружается один раз и может запускаться сколько угодно раз с разными контролами и сидами — запуски независимы.

## Встроенные функции

| Функция | |
|---|---|
| `floor ceil round abs sqrt exp log(x[, base])` | математика |
| `min(...) max(...)` | по числам и элементам массивов |
| `sum(arr) len(arr)` | сумма всех элементов / длина первого измерения |
| `create_array(n1, n2, ..., value=0)` | массив заданной формы |
| `uniform(a=0, b=1)` | равномерное на `[a, b]` |
| `normal(mu=0, sigma=1)` | нормальное `N(mu, sigma²)` |
| `exponential(mean)` | экспоненциальное со средним `mean` (интенсивность `1/mean`) |
| `bernoulli(p)`, `poisson(lambda)` | 1 с вероятностью `p` / число Пуассона |

Случайные функции используют сид модели: каждый вызов — новое независимое значение, один и тот же сид даёт те же значения.
Их можно использовать везде, кроме `default` у controls: в `do`, в `every` и `after`, в вероятностях `choose`.
Аргументы-длительности переводятся в дни: `emit Done after exponential(mean=30m)`, `trigger { every uniform(1h, 3h) }`.

## Ошибки

Все наследуются от `MagnumError` и содержат `line`/`column`, где это возможно:
`MagnumSyntaxError` (грамматика), `MagnumValidationError` (неизвестное событие/функция, неверное число аргументов, `trigger` у события с параметрами, нарушение `limits` значением по умолчанию …),
`MagnumControlError` (неверные контролы при запуске), `MagnumRuntimeError` (деление на ноль, неопределённая переменная, сумма вероятностей > 1, бесконечная цепочка `emit` без задержки — превышен `max_events`).
