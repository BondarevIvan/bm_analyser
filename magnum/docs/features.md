# Улучшения языка Magnum

Список возможных улучшений языка, которые ускоряют моделирование и упрощают модели.
Основа — профилирование модели кофейни (`models/coffee.mgn`, 30 дней): из ~81 тыс. событий только около
пятой части — полезная работа, остальное — обходные пути, которыми модель заменяет недостающие конструкции языка.

Порядок — по убыванию ожидаемого эффекта.

| # | Улучшение | Эффект | Статус |
|---|---|---|---|
| 1 | Триггер `when` — ожидание условия вместо опроса | убирает холостые события (~80% в кофейне) | **реализовано** |
| 2 | Встроенные очереди и ресурсы | O(1) операции, нет копирования массивов, модели вдвое короче | **реализовано** |
| 3 | Отмена запланированного события | убирает лишние срабатывания таймеров | идея |
| 4 | Детерминированное ветвление `when ... else` | не тратит случайные числа на заранее известный исход | идея |
| 5 | Локальные переменные `let` | короче запись, быстрее доступ, нужно для кодогенерации | идея |
| 6 | Календарь и неоднородные потоки | `hour(TIME)`, расписания, `arrival` с переменной интенсивностью | идея |
| 7 | Статистика в модели (`observe`) | среднее/дисперсия/гистограмма без хранения рядов | идея |
| 8 | Статические типы (число / массив) | меньше проверок во время выполнения, нужно для кодогенерации | идея |

## 1. Триггер `when` — ожидание условия вместо опроса

**Проблема.** Мастер в кофейне раз в минуту проверяет, не появился ли клиент (`emit ExecuteOrder after 1m`).
Это ~64 тыс. из ~81 тыс. событий за 30 дней, к тому же клиент ждёт начала обслуживания лишние ~30 с.

**Решение.**
```
event StartOrder {
    trigger { when idle_masters > 0 and ptr < queue_size }
    do { ... }
}
```
Событие срабатывает, когда условие истинно. Движок при загрузке определяет, от каких глобальных переменных
зависит условие (в том числе через вызываемые функции модели), и проверяет его только после событий,
которые эти переменные изменили. Холостых событий нет.

Подробная семантика — в `GRAMMAR.md`, раздел «Триггеры».

## 2. Встроенные очереди и ресурсы

**Проблема.** Половина кода кофейни — ручная очередь: массив на 1000 элементов, `ptr`, `queue_size`,
пометки 0/1, ежедневный сброс, пропуск ушедших. При `sampling="on_change"` массив копируется на каждом изменении.

**Решение (реализовано).** Очередь и ресурс создаются присваиванием только в `controls` или в `do`:
```
controls { default { masters = resource(capacity = count_masters) } }
event _init { do { clients = queue() } trigger { on start } }

push clients(client_id)
remove clients(client_id)        # клиент ушёл
instant[next] = pop clients
seize masters  /  release masters
```
Функции `size`, `first`, `contains`, `free`, `busy`, `capacity`. Операции за O(1), без копирования.
Подробности — `GRAMMAR.md`, раздел «Очереди и ресурсы»; пример — `models/coffee_queue.mgn`.

## 3. Отмена запланированного события

**Проблема.** На каждого клиента планируется `ClientLeave`, который срабатывает и у уже обслуженных.

**Решение.**
```
emit ClientLeave(pos) after patience as leave_timer
...
cancel leave_timer
```

## 4. Детерминированное ветвление вместо `choose` с вероятностями 0/1

**Проблема.** `choose { instant[has_order]: ... }` тратит случайное число на каждое срабатывание, даже когда
исход известен. Это ещё и сдвигает поток случайных чисел: правка логики в одном месте меняет
случайные результаты в другом.

**Решение.**
```
when has_order:  emit ExecuteOrder after delay
else:            emit ExecuteOrder after 1m
```
`choose` остаётся только для настоящей случайности.

## 5. Локальные переменные `let`

`let delay = exponential(...)` вместо `instant[delay] = ...`: короче, а движок при загрузке знает все локальные
переменные события и может держать их в слотах вместо словаря. Условие для генерации Python-кода из модели.

## 6. Календарь и неоднородные потоки

- функции `hour(TIME)`, `day(TIME)`, `weekday(TIME)` вместо своих `mod`/`floor`;
- расписание работы: `schedule open { 08:00 - 22:00 }`;
- `arrival poisson(lambda = profile[hour(TIME)], per=1h)` — поток с меняющейся интенсивностью,
  прореживание делает движок. Заодно снимается ограничение: сейчас при `lambda = 0` поток останавливается навсегда.

## 7. Статистика в модели

```
observe wait_time = TIME - arrival_time     # движок копит среднее, дисперсию, гистограмму
```
Быстрее и экономнее, чем `on_change`, и прямо то, что нужно для калибровки модели по реальным данным —
распределения наблюдаемых величин.

## 8. Статические типы

Если при загрузке известно, какая переменная — число, а какая — массив, большинство проверок во время
выполнения не нужны. Вместе с `let` это позволяет генерировать из модели Python-код (оценка — ещё ×3 к скорости).

---

**Оценка для кофейни:** пункты 1–3 сокращают число событий с ~81 тыс. до ~13–15 тыс. (×5–6),
код модели — примерно вдвое. Кодогенерация (5, 8) — ещё примерно ×3.
